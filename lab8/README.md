# Практическая работа 8. Лямбды и Stream API

## Запуск

Нужны JDK 21 и Maven. В PowerShell из папки `E:\Java-edu\lab8`:

```powershell
mvn test
java -cp target/classes coursehub.practice8.Practice8
```

Исходный код — `src/main/java/coursehub/practice8/Practice8.java`, тесты — `src/test/java/coursehub/practice8/Practice8Test.java`. После `mvn test` запускаются JUnit-проверки; `main` печатает небольшой пример. `record` — краткая форма неизменяемой модели: Java генерирует конструктор, методы чтения, equals и hashCode. Список модулей копируется в конструкторе, поэтому внешнее изменение списка не изменит курс.

## Модель данных

`Course` хранит код, уровень `Level`, длительность в часах и список тем модулей. Код не может быть пустым, уровень — null, а длительность — неположительной. Результаты методов возвращаются в виде неизменяемых коллекций, где это оговорено в коде. `EnumMap` хранит данные по значениям перечисления, а `TreeMap` и `TreeSet` дают сортировку ключей.

## 1. Сортировка и детерминизм

`COURSE_ORDER` последовательно сравнивает уровень, длительность, код и список модулей. Последний дополнительный критерий разрешает совпадение первых трёх полей. `compareModules` сравнивает элементы списка по очереди, затем длины. Это не зависит от разделителей внутри строки: например, одна тема с нулевым символом и две темы не считаются одинаковыми из-за склейки.

`sortedCourses` строит поток, применяет `sorted(COURSE_ORDER)` и собирает список через `toList()`. Одинаковый набор курсов даёт одинаковый порядок при разном порядке входа. Совершенно одинаковые записи неразличимы по значениям. Тест проверяет в том числе совпадение основных ключей.

## 2. flatMap

`normalize` удаляет крайние пробелы, схлопывает внутренние Unicode-пробелы и переводит строку в нижний регистр с `Locale.ROOT`. Пустые темы после нормализации пропускаются. Это упрощённая нормализация, а не полное Unicode case folding.

`topics` вызывает `flatMap(c -> c.modules().stream())`: каждый курс превращается в поток его тем, а flatMap объединяет эти потоки в один. Результат попадает в `TreeSet`, который убирает дубликаты и сортирует темы. `topicIndex` аналогично создаёт пары «нормализованная тема — код курса», группирует их в `TreeMap<String, Set<String>>` и сохраняет коды в `TreeSet`. Вручную список списков не создаётся.

## 3. reduce и identity

`totalDuration` вызывает `reduce(0L, Math::addExact)`: ноль — нейтральный элемент, так как `0 + x = x`. `Totals` объединяет количество и сумму; `totals` начинает с `(0, 0)` и применяет `Totals::combine`. Это отдельный неизменяемый объект результата.

`wrongIdentity` намеренно начинает сумму с 10: для курсов на 10 и 20 часов получится 40 вместо 30, а на пустом списке — 10. Аккумулятор для параллельного reduce должен быть ассоциативным: `(a + b) + c = a + (b + c)`, а identity — нейтральным. Здесь используется `Math.addExact`: при переполнении возникает исключение. При допустимых неотрицательных значениях результат сложения одинаков для разных группировок, если он помещается в long.

## 4. Collectors

`byLevel` использует `groupingBy` с downstream `summarizingInt`: каждый курс попадает в свою группу, где одновременно считаются количество, сумма, минимум и максимум. `collectingAndThen` преобразует статистику в `LevelSummary(count, total, average)`. Это один проход по исходному списку курсов, а не три независимых stream-прохода. Группы без курсов в карте отсутствуют.

## 5. Optional

`longestLabel` сортирует курсы по убыванию длительности, а при равенстве — по коду; `findFirst()` возвращает `Optional<Course>`. `map` формирует строку, а `orElse("Курсов нет")` задаёт результат пустого списка. `get()` не используется, `Optional` не хранится в поле сущности. Сортировка здесь удобна для наглядного tie-breaker, но для большого потока `min` с тем же компаратором обошёлся бы без полной сортировки.

## 6. Собственный collector

`Stats` — неизменяемый результат: число, сумма, необязательные min и max. `StatsAccumulator` — изменяемое временное состояние **одной** частичной обработки, а не static-поле.

`statsCollector` передаёт в `Collector.of` четыре операции: supplier создаёт пустой аккумулятор, accumulator добавляет курс, combiner объединяет две части, finisher превращает временное состояние в `Stats`. Для пустого потока min/max отсутствуют. Операция merge учитывает пустые части и подходит параллельному разбиению; тест сравнивает sequential и parallel результаты. Готовый `Collectors.summarizingInt` уже решает аналогичную задачу; свой collector полезен, когда нужен собственный тип или специфический контракт.

## 7. Однопроходный отчёт CourseHub

`EnrollmentEvent(student, courseCode, completed)` — событие о состоянии заявки. Контракт отчёта:

1. Входной поток событий последовательный и проходится ровно один раз. Метод потребляет stream, но не закрывает его: ресурс, например `Files.lines`, закрывает вызывающий код через try-with-resources.
2. Учитываются только события по кодам из каталога. Неизвестный код — аномалия; такой студент не включается в счётчик известных заявок.
3. Одна пара «студент — курс» считается одной заявкой. Повтор увеличивает счётчик аномалий, а признаки завершения объединяются через OR: если хотя бы одно событие завершено, заявка завершена. Поэтому перестановка событий не меняет итоги.
4. `studentIds` содержит уникальных студентов в отсортированном порядке, `courses` содержит все курсы, в том числе без заявок. Completion rate — завершённые уникальные заявки / все уникальные заявки; для нуля заявок возвращается 0. `top3` — три курса с наибольшим числом заявок, при равенстве коды сортируются по алфавиту. Распределение по level считает уникальные заявки, а не уникальных студентов.
5. `anomalyCount` считает все события с аномалиями. `anomalies` хранит не более `maxAnomalies` различных описаний в лексикографическом порядке; если описаний больше, остаются лексикографически первые. Поскольку одинаковые сообщения объединяются, размер списка может быть меньше счётчика.

`pairs` — карта уникальных пар и статуса завершения, `students` — множество уникальных студентов, `counts` — статистика по каждому коду. Точный подсчёт уникальных студентов и пар требует памяти, растущей с их числом; список аномалий ограничен заданным лимитом. Это не алгоритм с постоянной памятью при неограниченном числе уникальных идентификаторов. Для строго ограниченной памяти нужна внешняя база/сортировка либо приближённый алгоритм с другим контрактом.

Метод не записывает файлы и не меняет входной каталог; изменяемые карты находятся внутри вызова. Это не «отсутствие мутаций», а отсутствие внешних побочных эффектов. Для обработки самих событий обычный цикл понятнее комбинации нескольких stateful-коллекторов: все показатели обновляются в одном месте. Для сортировки готового небольшого результата Stream API удобен и применяется отдельно. Параллельный поток отклоняется, чтобы контракт накопления оставался явным.

## Как объяснить код по шагам

`events.iterator()` получает однократный итератор; `while (iterator.hasNext())` читает очередное событие, не сохраняя все события. Для известного курса создаётся `Pair`, затем `putIfAbsent` сообщает, встречалась ли пара раньше. При повторе старое и новое состояние объединяются. После конца потока выполняется обход уже накопленных уникальных пар, чтобы получить итоги по курсам; повторного чтения исходного потока нет. `List.copyOf` и неизменяемые обёртки не позволяют изменять опубликованный результат.
