# Лабораторная работа 6. Строки, числа и время

## Где что находится

Код расположен в `src/main/java/coursehub/practice6/`. Основные модели и операции теперь находятся в отдельных файлах:

- `CourseCode`, `CourseTitle` и `ReportBuilder` — проверка кода, нормализация названия и сборка строк.
- `IntegerPolicy`, `RandomSampleService`, `DiscountAllocator`, `Money` — числа и денежная арифметика.
- `DateParser`, `InvalidDateFieldException`, `LocalDateTimeResolver`, `InvalidLocalTimeException` — строгий разбор даты и правила часового пояса.
- `WebinarSeriesPlan`, `Purchase`, `PricingService`, `RefundService` — расписание, покупка, скидка и возврат.
- `Practice6` и `ExtraExamples` содержат демонстрации; `Practice6Test` — тесты.

## Как запустить

Нужны JDK 21 и Maven 3.8+. В папке `lab6`:

```powershell
mvn test
java -cp target/classes coursehub.practice6.Practice6
java -cp target/classes coursehub.practice6.ExtraExamples
```

`Practice6.java` и `ExtraExamples.java` запускают примеры; модели и операции расположены в отдельных файлах, `Practice6Test.java` содержит JUnit-тесты. `record` генерирует конструктор и методы чтения компонентов; например, денежная модель объявлена в `Money.java`. Первый запуск Maven скачивает зависимости. Если в консоли вместо русских букв отображаются неверные символы, проверьте кодировку терминала UTF-8.

## 1. String: ссылка и содержимое

В `ExtraExamples`: `literal` — литерал, `compile` — результат конкатенации констант, `fromNew` создан через new, `runtime` — результат вычисления при работе программы. `==` сравнивает ссылки, `equals` — текст. Литерал и compile-time конкатенация интернированы; `new String` создаёт новый объект. `intern()` возвращает каноническую ссылку из пула. Для обычного сравнения текста используйте `equals`, не завися от пула; если первая строка может быть null — `Objects.equals(a,b)`.

## 2. Сборка строки

`reportPlus(10000)` в цикле создаёт новое содержимое при каждом присваивании: `String` неизменяем. `reportBuilder` добавляет строки в изменяемый буфер, а один итоговый String создаёт в конце. `ExtraExamples` сравнивает результаты и время через `System.nanoTime`; это демонстрация, не JMH: нет прогрева, статистики и контроля оптимизаций, поэтому цифры могут сильно отличаться.

## 3. Регулярное выражение

`CourseCode.parse` использует `([A-Z]{2,10})-([0-9]{3})`: первая группа — 2–10 заглавных ASCII-букв, вторая — ровно три ASCII-цифры. `matches()` требует совпадения всей строки, не только фрагмента. `Integer.parseInt` превращает вторую группу в число: ведущие нули в числовом значении теряются.

| Вход | Итог |
|---|---|
| `JAVA-101` | prefix JAVA, number 101 |
| `AB-001` | prefix AB, number 1 |
| `JAVA-101x` | отказ: лишний текст |
| ` JAVA-101` | отказ: пробел |
| `java-101` | отказ: строчные буквы |
| `ЯВА-101`, `JAVA-１２３` | отказ: Unicode вне ASCII |

## 4. Autoboxing

`Integer` — объект-обёртка, `int` — примитив. Автоматическое извлечение `int n = absent` при null выбрасывает NPE; пример его перехватывает только для демонстрации. `requireInteger` явно запрещает null с понятным сообщением. `==` для двух Integer сравнивает ссылки; часть значений может кэшироваться, поэтому использование `==` ненадёжно. Сравнивайте значения через `equals`/`Objects.equals` либо проверяйте null перед распаковкой.

## 5. BigDecimal и double

`new BigDecimal(0.1)` точно отражает уже неточное двоичное значение double и показывает длинный хвост. `BigDecimal.valueOf(0.1)` использует строковое представление double, а `new BigDecimal("0.1")` сразу создаёт указанное десятичное число. Для денег берите строки или целые минимальные единицы. В примере три суммы `0.10 + 0.20 + 0.30 = 0.60`.

## 6. Распределение скидки

`allocateDiscount(prices, discount, rounding)` проверяет валюты и неотрицательные значения; скидка не может превышать сумму. Первоначально каждая доля считается пропорционально цене и округляется переданным `RoundingMode`. После этого может остаться разница в несколько минимальных единиц: цикл добавляет или снимает их последовательно по индексам, не позволяя доле стать отрицательной или больше цены. Возвращается список скидок, сумма которых равна исходной скидке. Пустой список отклоняется. `RoundingMode.UNNECESSARY` может выбросить исключение, если дробь требует округления; это соответствует выбранному режиму.

## 7. Math и случайность

`randomSample` получает `RandomGenerator` снаружи, число элементов и диапазон `[lower, upperExclusive)`. В тесте `new Random(7)` с одинаковым seed даёт повторяемую последовательность; в production источник выбирается в зависимости от задачи, для секретов нужен криптографический генератор, например `SecureRandom`. Пример показывает `Math.min`, `Math.max`, `Math.round`. Округление денег выполняется отдельно через BigDecimal и явный режим, не через double.

## 8. Календарь

`LocalDate` хранит дату без времени и зоны. В примере старт — 29.02.2024, следующие модули получаются через `plusWeeks`; последний день — `plusDays(20)`. Методы возвращают новые объекты: исходная дата не изменяется. `isLeapYear()` определяет високосный год. В реальном расписании праздники и выходные потребуют дополнительных правил.

## 9. Period и Duration

В Berlin 30 марта 2024 в 12:00 добавление `Period.ofDays(1)` даёт 31 марта 12:00 по местному времени; из-за перехода на летнее время прошло 23 часа. Добавление `Duration.ofHours(24)` даст 13:00 следующего дня. `Period` подходит для календарного срока подписки, `Duration` — для таймаута и измеряемого промежутка времени.

## 10. Строгая дата

`parseDate(field,value)` применяет `dd.MM.uuuu` и `ResolverStyle.STRICT`. `uuuu` — год, `MM` — месяц, `dd` — день; строгое разрешение отклоняет 29.02.2023 и лишний текст. При ошибке `InvalidDateFieldException` включает имя поля и исходный ввод, а исходный `DateTimeParseException` доступен через `getCause()`.

## 11. Момент и зоны

`Instant` — абсолютный момент на временной шкале. `ExtraExamples` показывает один момент в UTC, Asia/Novosibirsk и America/New_York через `instant.atZone(zone)`. Часы на экране разные, момент тот же. Явный `ZoneId` исключает неявную зависимость бизнес-результата от зоны сервера.

## 12. DST: пропуск и повтор

В Europe/Berlin 31.03.2024 локальное время 02:30 отсутствовало: часы перевели вперёд. Обычный `ZonedDateTime.of` сдвигает такой ввод вперёд; `LocalDateTimeResolver.resolve` вместо этого отвергает его через `InvalidLocalTimeException`, чтобы занятие не перенеслось незаметно. При осеннем повторе 27.10.2024 02:30 существуют два offset: аргумент `secondOffset` выбирает первый или второй, соответствующие моменты разнесены на час. `plusHours` прибавляет длительность, `plusDays` сохраняет местный календарный смысл с учётом правил зоны.

## 13. Нормализация поиска

`CourseTitle.of` сохраняет `display` после удаления крайних пробелов и строит отдельный `searchKey`: схлопывает внутренние Unicode-пробелы и переводит в нижний регистр с `Locale.ROOT`. Например, `" Java  Basics "` и `"java basics"` дают одинаковый ключ при разных отображаемых значениях. Это **конфликт поиска**, поэтому ключ не следует считать уникальным ID. `toLowerCase` — упрощённая нормализация, не полное Unicode case folding и не нормализация NFC; если они нужны, контракт следует расширить.

## 14. Money

`Money(amount, currency)` — record с неизменяемыми `BigDecimal` и `Currency`. Конструктор приводит масштаб к числу дробных разрядов валюты с `UNNECESSARY`: потеря точности запрещена, поэтому `1.0 RUB` и `1.00 RUB` нормализуются к одному масштабу и равны. `add` и `subtract` сначала проверяют одинаковую валюту; `percentage` принимает BigDecimal и явный режим округления. `allocate(parts)` делит неотрицательную сумму на равные части в минимальных единицах и выдаёт остаток первым элементам. `10.00 / 3` → `3.34, 3.33, 3.33`. Никакого double в API нет. Отрицательные суммы допустимы как результат вычитания, но распределение отрицательной суммы запрещено.

## 15. Продажа и возврат

`WebinarSeriesPlan.weekly` получает первое местное время и зону организатора, создаёт следующие локальные даты через `plusWeeks`, разрешает каждую в этой зоне и хранит моменты как список `Instant`. При gap создание всего плана завершается ошибкой, при overlap выбирается первый offset. Поэтому один и тот же часовой слот остаётся локальным после смены DST, хотя UTC-смещение может измениться.

`price` применяет скидку только когда `now.isBefore(deadline)`: в сам момент deadline цена уже полная. Значение процента 0–100 проверяется, округление передаётся явно. `Purchase` связывает оплаченную сумму и план. `refund` считает занятия строго после `now`: занятие, которое уже началось ровно в этот момент, не считается оставшимся. Возврат равен `paid * remaining / total`, округление явно задаёт вызывающий. Валюта сохраняется. `LocalDate` описывает календарную дату; `ZonedDateTime` нужен для локального расписания и правил зоны; `Instant` для сравнения реальных моментов; `Period` для календарных сроков, `Duration` для длительностей, `BigDecimal` для десятичной денежной арифметики. Тесты охватывают leap day, gap/overlap, границу скидки, валюты и округление.
## Разбор основных методов по шагам

`CourseCode.parse` создаёт Matcher для полного входа, вызывает `matches`, при отказе выбрасывает исключение. При успехе `group(1)` и `group(2)` возвращают захваченные части, вторая преобразуется в число.

`resolve` получает правила зоны и список допустимых смещений для локального времени. Если список пуст, время находится в пропуске и создаётся исключение. Иначе выбирается первый offset либо второй, если он есть и явно запрошен; `ofStrict` проверяет соответствие времени, смещения и зоны.

В конструкторе `Money` `currency.getDefaultFractionDigits()` задаёт масштаб. `setScale(..., UNNECESSARY)` дополняет недостающие нули, но запрещает потерю ненулевых цифр. `same` сравнивает валюты до арифметики. `allocate` переносит десятичную точку так, чтобы получить целое количество копеек, затем `divideAndRemainder` возвращает базовую долю и остаток. Первым позициям добавляется по одной копейке.

`WebinarSeriesPlan.weekly` не прибавляет к Instant фиксированное число секунд: он прибавляет недели к локальному времени и отдельно разрешает каждый результат в зоне. Это сохраняет местное время занятия при смене смещения. `price` сравнивает два Instant, а `refund` фильтрует только будущие занятия и делит оплаченную сумму пропорционально их числу с явно переданным округлением.
