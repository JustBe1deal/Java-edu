# Лабораторная работа № 7. Файлы и потоки в Java

Программа хранит каталог курсов и последовательно демонстрирует девять заданий. Внешние библиотеки не нужны; требуется JDK 11 или новее. Исходники находятся в `src/Lab7.java`, самостоятельные проверки — в `src/Lab7Test.java`.

## Запуск в PowerShell

Находясь в папке `lab7`:

```powershell
javac -encoding UTF-8 -d out src/Lab7.java src/Lab7Test.java
java -cp out Lab7Test
java -cp out Lab7
```

Пример создаёт папку `lab7-output` в текущем каталоге и перезаписывает в ней файлы с именами, используемыми демонстрацией. Можно указать другую папку: `java -cp out Lab7 C:\temp\my-courses`. Тесты создают временный каталог и удаляют его после выполнения. Компиляция требует именно JDK: команда `javac` должна находиться в PATH.

## Модель и текстовый формат

`Course` — неизменяемая запись: положительный `id`, непустое название и положительное число часов. `parse` разбирает одну строку `id|название|часы`, например `1|Алгоритмы|72`. Разделитель и переводы строк в названии запрещены. Каждая запись занимает строку, кодировка — UTF-8; пустая строка считается ошибкой. Уникальность id не проверяется.

## 1. Files.readString/writeString

`writeString` записывает каталог целиком, `readString` возвращает текст целиком. Оба явно выбирают UTF-8 и передают `IOException` вызывающему коду, если файла нет, вместо файла указан каталог или произошла другая ошибка. Метод не сообщает об успехе после ошибки. Эти методы удобны для небольших файлов, поскольку загружают данные в память целиком.

## 2. Reader и Writer

`copyBuffered` открывает `BufferedReader` и `BufferedWriter`, копирует текст посимвольно и возвращает `Counts`: число строк и количество единиц UTF-16, включая символы окончания строки. CRLF считается одним окончанием строки; завершающий перевод строки не создаёт дополнительную пустую строку. Пустой файл содержит ноль строк. Копирование сохраняет исходные окончания строк.

На границе байтов и символов декодер reader превращает байты UTF-8 в символы Java, а writer кодирует их обратно в UTF-8. Символ в смысле счётчика — единица `char` UTF-16: например, эмодзи вне BMP занимает две такие единицы, а не одну. Два разных пути могут ссылаться на один файл через ссылки: передавайте разные файлы.

## 3. Try-with-resources

`pipelineFailure` открывает reader, затем writer, читает первый символ, записывает его и выбрасывает исключение. Переопределённые `close` добавляют событие только после фактического закрытия ресурса. Ожидаемая последовательность: `close writer`, `close reader`, затем обработка исключения. Ресурсы закрываются в обратном порядке объявления. Если закрытие тоже завершится ошибкой, она будет добавлена к основному исключению как suppressed; метод не скрывает её. Выходной файл при этом может быть частичным: это учебная демонстрация, а не атомарная запись.

## 4. Ленивые строки

`countLines` обрабатывает `Files.lines` внутри try-with-resources. Поток читает файл лениво и владеет открытым ресурсом; закрыть его обязан тот, кто его открыл, либо явно принявший владение вызывающий код. `brokenLines` специально возвращает уже закрытый stream: терминальная операция снаружи вызовет `IllegalStateException`. Это пример ошибки, а не рекомендуемый API.

## 5. Бинарный формат

`writeBinary` и `readBinary` используют `DataOutputStream` и `DataInputStream`: 4-байтовый magic `COUR`, целочисленные версия `1` и количество записей, затем `int id`, `writeUTF(title)`, `int hours`. Порядок байтов целых чисел — big-endian. `writeUTF` использует modified UTF-8 и ограничивает закодированную строку 65535 байтами; это не то же самое, что обычный UTF-8 текстового файла. Читатель проверяет magic, версию, число записей, корректность полей и отсутствие хвоста; обрезанный файл приводит к `IOException`. Результат возвращается только после полного чтения.

## 6. Временный файл и замена

`saveReplace` создаёт временный файл в родительском каталоге цели, записывает данные, вызывает `flush` и закрывает writer до перемещения. Сначала запрашивается `ATOMIC_MOVE` с заменой; при `AtomicMoveNotSupportedException` выполняется обычный `REPLACE_EXISTING`. Возвращаемый `MoveResult` показывает, какой вариант использован. Обычная замена не гарантирует атомарность; другие ошибки не маскируются. Временный файл удаляется в `finally`. `flush` и закрытие не являются гарантией сохранения на физический носитель при сбое питания; для такой гарантии нужны дополнительные механизмы файловой системы.

## 7. Частично повреждённый импорт

`importAtomic` реализует контракт **all-or-nothing**: все строки проверяются, ошибки содержат номера строк с единицы, и при хотя бы одной ошибке `courses` пуст. При успехе возвращается неизменяемый полный список. `ImportResult.success()` отличает успешный пустой каталог от ошибки; `valid` сообщает число корректных строк даже при неуспехе. При ошибке чтения метод выбрасывает исключение и не возвращает результат. Метод хранит записи и все ошибки в памяти, поэтому предназначен для файлов умеренного размера. Дубликаты id допустимы.

## 8. Большой файл

`scanLarge(path, maxErrors, stopAfterErrors)` обрабатывает по одной строке через `BufferedReader`, не вызывает `readAllLines` и не хранит каталог. Он считает прочитанные строки, корректные записи и все обнаруженные ошибки, сохраняя не больше `maxErrors` подробностей. После ошибки номер `stopAfterErrors` останавливается и устанавливает `cancelled`; этот флаг означает, что сработал порог, даже если ошибка оказалась последней строкой файла. `courses` всегда пуст: метод предназначен для проверки и статистики, а не публикации. Память зависит от ограниченного списка ошибок и размера самой длинной строки; для неограниченно длинной строки потребовался бы посимвольный парсер с лимитом длины.

## 9. Версионирование и миграция

`writeVersioned`/`readVersioned` используют отдельный от задания 5 формат: `magic`, `version`, длина payload, payload, CRC32 от байтов payload. В payload v1 хранятся количество и пары `id`, `title`; в v2 после названия добавляется `hours`. Миграция v1 в объект v2 задаёт отсутствующим часам значение **1**. Это учебное значение по умолчанию, а не восстановление исходных данных. При записи v1 часы теряются.

Читатель отвергает неизвестную версию, неверную длину, обрезанные данные, несовпадающую CRC, лишние байты и некорректные поля. Сначала он полностью проверяет CRC, затем создаёт объекты и возвращает неизменяемый список только после проверки всего payload. CRC32 обнаруживает случайные повреждения payload, но не защищает от намеренной подмены и не покрывает заголовок. Размер payload при чтении ограничен 64 МиБ; реализация этого задания загружает его целиком и не предназначена для больших файлов из задания 8.

## Проверки

`Lab7Test` проверяет UTF-8, отсутствующий файл и каталог вместо файла, копирование и подсчёт, порядок закрытия, закрытый stream, бинарный round-trip, обрезку и неизвестную версию, импорт с ошибками и его порог, замену файла, миграцию, checksum и повреждённые версионированные файлы. Ветка отказа от атомарного move зависит от файловой системы и в обычном тесте принудительно не воспроизводится.
