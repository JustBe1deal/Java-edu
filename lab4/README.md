# Лабораторная работа 4. Исключения и тестирование

## Запуск

Нужны JDK 21 и Maven. В PowerShell из `lab4` выполните `mvn test`, затем `java -cp target/classes coursehub.practice4.Practice4` для демонстрации stack trace и finally. Исходный код — `src/main/java/coursehub/practice4/Practice4.java`, тесты — `src/test/java/coursehub/practice4/Practice4Test.java`. Тесты не используют общих изменяемых static-полей, текущую папку и порядок выполнения. `pom.xml` подключает JUnit Jupiter, compiler plugin и Surefire.

## 1. Чтение stack trace

Цепочка `first -> second -> third -> fourth` передаёт число вниз. `fourth` выбрасывает `IllegalArgumentException` с сообщением «значение должно быть положительным», если число <= 0. В stack trace первая строка содержит тип и сообщение; верхний кадр укажет `fourth` и номер строки, ниже — `third`, `second`, `first` и вызвавший код. Исправлять нужно входное значение или логику его получения, а не удалять последний кадр. `first(1)` завершится успешно.

## 2. Выбор способа сообщить об ошибке

| Ситуация | Выбор | Почему |
|---|---|---|
| Отрицательный обязательный аргумент | unchecked `IllegalArgumentException` | Нарушен контракт вызывающим кодом. |
| `null` там, где он запрещён | unchecked `NullPointerException` | Ошибка использования API, `requireNonNull` показывает место. |
| Отсутствующий файл при импорте | checked `IOException`/инфраструктурная ошибка | Ожидаемый внешний отказ, вызывающий решает, что делать. |
| Недоступная сеть | checked или типизированный инфраструктурный результат | Отказ вне контроля программы; возможны повтор или сообщение пользователю. |
| Операция при неправильном состоянии объекта | unchecked `IllegalStateException` | Нарушена последовательность вызовов. |
| Некорректная обязательная конфигурация при запуске | исключение конфигурации, остановка запуска | Работа без настроек невозможна; важно сообщить поле. |
| Пользователь не найден при обычном поиске | `Optional.empty()` | Ожидаемое отсутствие, не авария. |
| Нет места на курсе | типизированный отказ | Обычный исход бизнес-операции. |
| Неправильная строка импортируемого файла | checked `CourseImportException` | Нужны номер записи и причина; импорт прекращается. |
| Недостаток памяти | `OutOfMemoryError`, обычно не восстанавливаемся | Это не бизнес-отказ; общий catch ради продолжения ненадёжен. |

В конкретной системе checked/unchecked граница может отличаться; решение зависит от контракта и способности вызывающего восстановиться.

## 3. Собственное исключение

`EnrollmentRejectedException` хранит `studentId`, `courseId`, `Reason` и причину в `cause` через `super(message, cause)`. Сообщение содержит только стабильный код причины, не ID или исходный текст; стандартный `toString` использует имя класса и это сообщение. Сам `cause` доступен разработчику, и полный stack trace может раскрывать его детали — не отправляйте его автоматически пользователю.

## 4. try/catch/finally

`finallyExample(false, log)` записывает `try`, затем `finally` и возвращает `try result`. При `true`: `try`, `catch`, `finally`, результат `catch result`. `finally` выполняется до завершения return или распространения исключения. Если из `finally` сделать `return`, он заменит предыдущий return и способен скрыть исключение; поэтому код не возвращает значение оттуда. Аварийное завершение процесса не гарантирует выполнение finally.

## 5. Try-with-resources

`TracedResource` пишет open/use/close. `traced` закрывает ресурс и при обычной работе, и при исключении из `use`. Если `use` и `close` оба выбросили `IOException`, основной остаётся ошибка use, а ошибка close доступна через `getSuppressed()`. Тесты проверяют оба сообщения и порядок. Для нескольких ресурсов закрытие происходит в порядке, обратном объявлению.

## 6. Перевод на границе импорта

`parseCourse` разбирает `id|duration`. Вызов `Integer.parseInt` может бросить `NumberFormatException`; метод переводит её в `CourseImportException(record, cause)`. Ошибку доменной проверки он тоже оборачивает с номером записи. Исходная причина доступна через `getCause()`. Ловятся конкретные типы, а не все ошибки подряд.

## 7. Ошибка или значение

`findCourse` возвращает `Optional<Course>`: отсутствие — нормальный результат поиска. `enroll` возвращает `Decision`, где отказ содержит `Reason`: нет мест или prerequisite — ожидаемые исходы. `parseCourse` применяет checked-исключение: вызывающий обязан обработать неудачный импорт. Некорректный аргумент расчёта или объекта — unchecked исключение, поскольку вызывающий нарушает контракт. В этой лабораторной отдельный `calculatePrice` не реализован; тот же подход к денежной модели показан в лабораторной 6.

## 8–12. Тесты

`completeHoursAddsProgress` разделён комментариями на Arrange (создание курса), Act (вызов), Assert (ожидание); он проверяет один результат. В параметризованном тесте продолжительности проверяются 0, 1, 1000, 1001. Обычный пример внутри диапазона не выявил бы ошибку `<` вместо `<=` на границе.

`CourseCode` удаляет пробелы по краям и переводит в верхний регистр через `Locale.ROOT`, затем проверяет ASCII-шаблон. `@CsvSource` показывает вход и результат в имени, `@ValueSource` — неправильные коды. В `rejectionKeepsProgressAndMessage` lambda содержит только один вызов, который должен упасть; отдельно проверяются сообщение и неизменность `completed`. Каждый тест создаёт свой объект, не проверяет полный `toString` и не обращается к текущему каталогу.

Порядок проверок фиксирован: закрытый курс, повтор, prerequisite, места, успех. `*` означает, что значение больше не влияет на результат.

Параметризованный тест содержит по одному случаю каждой строки, а не все 16 комбинаций, которые дублировали бы правила. Таблица одновременно определяет приоритет, если причин отказа несколько.

## 14. Два отказа ресурса

`importCourses` принимает `Reader` и принимает на себя его закрытие. Записи собираются во временный список, который возвращается только после полного чтения и закрытия. В тесте вторая запись некорректна и `close` тоже выбрасывает исключение: основной результат — `CourseImportException` с `record == 2`, а ошибка закрытия лежит в `suppressed`. Значит, успешно разобрана одна запись, вторая вызвала отказ; список не опубликован. Если работа завершилась, но закрытие не удалось, возвращается `InfrastructureException` с причиной `IOException`.

## 15. Граница ошибок

Проверка конструктора `Course` защищает доменные инварианты; `Decision` представляет ожидаемый отказ зачисления; `CourseImportException` хранит номер записи и причину неверных входных данных; `InfrastructureException` сохраняет отказ чтения или закрытия. `importAndEnroll` сначала полностью импортирует каталог, затем находит курс и проверяет зачисление; он возвращает стабильный код и не публикует частичный каталог. Причина сохраняется в diagnostic для внутренней диагностики; пользовательскому интерфейсу следует отдавать только код. `publicError` отдельно переводит известные ошибки в стабильные коды и отвергает неизвестные типы. Он не ловит `Exception` вокруг всей операции: такой catch мог бы представить баг программы нормальным отказом и скрыть его. В тестовом классе более 20 отдельных тестовых сценариев с учётом параметризации. Тесты проверяют сообщения, причины, suppressed и состояние после отказа.
## Разбор основных методов по шагам

`Course.completeHours`: сначала условие отклоняет неположительное значение или число больше остатка `duration - completed`. Только после успешной проверки выполняется `completed += hours`; поэтому исключение не оставляет объект частично изменённым.

`parseCourse`: `split("\\|", -1)` делит по буквальному символу `|`, а `-1` сохраняет пустые поля в конце. После проверки количества полей `parseInt` преобразует их в int. Если преобразование не удалось, catch создаёт `CourseImportException` с номером записи и исходным исключением. Затем конструктор курса проверяет доменные границы.

`importCourses`: сначала создаётся временный список `staged`, затем try-with-resources берёт ответственность за reader. Каждая считанная строка повышает номер записи, преобразуется и добавляется в список. Если чтение, разбор или закрытие завершилось ошибкой, выполнение не доходит до `return List.copyOf(staged)`, поэтому список не публикуется. Исключение разбора проходит наружу; IOException преобразуется в инфраструктурное исключение.

`importAndEnroll` проверяет аргументы как контракты программиста; затем запускает импорт, поиск и политику. Только известные исключения импорта и инфраструктуры переводятся в стабильные коды. `diagnostic` содержит внутреннюю причину и не должен показываться конечному пользователю. Успех содержит найденный курс, отказы — null в этом поле.
