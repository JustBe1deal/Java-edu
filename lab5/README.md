# Лабораторная работа 5. Коллекции и generics

## Сборка и запуск

Нужны JDK 21 и Maven. В папке `lab5` выполните `mvn test`, затем `java -cp target/classes coursehub.practice5.Practice5` и `java -cp target/classes coursehub.practice5.ExtraExamples`. Исходники: `src/main/java/coursehub/practice5/Practice5.java` и `ExtraExamples.java`. Тесты находятся в `src/test`. Время в эксперименте зависит от компьютера, JVM и прогрева: результаты не являются микробенчмарком и их нельзя считать универсальными константами.

## 1. Список и порядок

`main` создаёт `ArrayList` регистраций, вставляет элемент по индексу, удаляет значение и передаёт список в `duplicates`. Метод создаёт `seen` и `duplicates`: `seen.add(item)` возвращает false для повторного значения, поэтому такое значение добавляется во второй set. Результат хранит каждый повтор один раз, в порядке первого обнаруженного повтора.

`ExtraExamples.measure` измеряет `get(i)` и обход for-each на 10 000 элементов. У `ArrayList` доступ по индексу O(1), обход O(n); у `LinkedList` получение элемента O(n), поэтому повторный доступ по всем индексам O(n²), но обход итератором O(n). LinkedList хранит дополнительные ссылки узлов; ArrayList иногда перераспределяет массив при росте. Замер учебный, без JMH и корректного прогрева.

## 2. Уникальность

`uniqueInOrder` создаёт `LinkedHashSet` и возвращает неизменяемый список: первый порядок появления сохраняется. `CourseCode` — record, поэтому equality и hash вычисляются по `value`. Равные значения обязаны иметь одинаковый hashCode. Регистр и пробелы здесь намеренно не нормализуются: `java` и `JAVA` — разные значения.

## 3. Индекс

`indexBy(items, key)` строит `LinkedHashMap`, вычисляя ключ функцией и используя `putIfAbsent`. При повторном ключе выбрасывает `IllegalArgumentException`, вместо молчаливого затирания. Null для элемента и ключа запрещён. `get(k)` возвращает значение или null; если null-значения разрешены, `containsKey(k)` отличит отсутствие от ключа с null. `putIfAbsent` вставляет, если значение отсутствует или равно null; в нашем индексе null запрещён. `computeIfAbsent` вычисляет значение по ключу при отсутствии, например создаёт set для тега.

## 4. Очередь

В `main` `Queue<String>` реализована через `ArrayDeque`. `offer` добавляет в конец, `peek` смотрит голову, `poll` извлекает голову; пустая очередь возвращает null. `add`, `remove`, `element` в соответствующих ситуациях отказа бросают исключение. Для ограниченной очереди `offer` может вернуть false при заполнении. `ArrayDeque` не допускает null, поэтому null от poll однозначно означает отсутствие элемента.

## 5. Удаление при обходе

В `ExtraExamples` удаление из списка непосредственно во время enhanced for воспроизводит `ConcurrentModificationException` при следующей проверке итератора. Это fail-fast диагностика, а не гарантия обнаружения любой гонки. Правильно: `Iterator.remove()` после `next()` либо `removeIf(predicate)`. Копия всего списка увеличивает расход памяти и может быть ненужной, если достаточно корректно удалить текущий элемент.

## 6–9. Generics

`Result<T>` создаётся через `success(value)` или `failure(error)`: null-успех и пустая ошибка запрещены. `value()` работает только для успеха, `error()` возвращает Optional. Можно иметь `Result<String>` и `Result<Integer>`; компилятор не даст присвоить Integer строковой переменной. Raw type не используется.

`firstOrThrow` возвращает первый элемент или `NoSuchElementException`, `swap` меняет позиции, `indexBy` работает с произвольными элементами и ключами. `max` использует bound `T extends Comparable<? super T>`: тип может сравниваться с самим собой или своим суперклассом. Примеры пригодных типов — Integer, String и собственный value object, реализующий `Comparable`.

`copy(List<? extends T> source, List<? super T> destination)` следует PECS: producer extends, consumer super. Из источника безопасно читать T, но добавлять конкретный T нельзя: реальный список может быть списком более узкого подтипа. В приёмник безопасно добавлять T; читать из него можно как Object, потому что реальный список может быть `List<Object>`.

## 10. Ключи

`Course` — record с финальными компонентами; set тегов защитно копируется. Его равенство и hash включают id, title и tags, все они неизменяемы. Для сущности, название которой меняется, предпочтительнее отдельный неизменяемый ключ ID. `ExtraExamples.MutableKey` намеренно включает изменяемое название в equals/hashCode: после изменения `HashSet.contains` может не найти объект в старой корзине. Именно поэтому ключ в hash-коллекции не должен менять участвующие в равенстве поля. `StableCourseKey` демонстрирует обратный случай в HashSet и HashMap: название меняется, но id остаётся прежним и поиск работает.

## 11. Выбор коллекций

| Нагрузка | Интерфейс и реализация | Основные операции и цена |
|---|---|---|
| Каталог по ID | `Map`, `HashMap` | Среднее O(1) get/put; порядок не гарантирован, есть память под таблицу. |
| Leaderboard по оценке | `NavigableMap`, `TreeMap` | O(log n) обновление и упорядоченный обход; нужен tie-breaker или список на одинаковый балл. |
| FIFO | `Queue`, `ArrayDeque` | Амортизированное O(1) на концах; null запрещён. |
| Теги с порядком | `Set`, `LinkedHashSet` | Среднее O(1), хранит связи порядка и тратит больше памяти. |
| Диапазон | `NavigableMap`, `TreeMap` | O(log n) поиск начала и O(k) обход k результатов. |
| Частый индекс | `List`, `ArrayList` | O(1) get, вставка в середину O(n), свободная ёмкость массива. |

## 12. Репозиторий

`Repository<ID,T>` задаёт `save`, `findById`, `findAll`, `deleteById`. `MemoryRepository` использует `LinkedHashMap`: повторный save заменяет значение по ID, null запрещён. `findAll` создаёт неизменяемый снимок списка: добавление нового объекта в репозиторий не меняет старый снимок. Сам объект T не копируется — если T изменяемый, вызывающий всё ещё может изменить его; глубокое копирование зависит от домена.

## 13. Обратный индекс

`TagIndex` хранит курсы по ID и `Map<String, Set<Integer>>`. `add` отказывает при повторном ID, затем для каждого тега создаёт set через `computeIfAbsent`. `remove` удаляет ID из каждого набора и убирает пустой set. `intersection` начинает со всех ID и оставляет только входящие в каждый из запрошенных наборов; пустой запрос соответствует всем курсам. LinkedHashMap/LinkedHashSet дают порядок добавления при обходе, hash-операции в среднем O(1).

## 14. LRU

`LruCache` использует `LinkedHashMap` с `accessOrder=true`: `get` переносит элемент в конец порядка. После вставки сверх ёмкости удаляется первый ключ — давно не использованный. Пример: при ёмкости 2 `put A`, `put B`, `get A`, `put C` оставит `[A, C]`, вытеснив B. Null ключи и значения запрещены; ключ должен иметь стабильные equals/hashCode. Класс не потокобезопасен.

## 15. Граф prerequisites

`Graph<T>` хранит в LinkedHashMap для каждой вершины LinkedHashSet её prerequisites. Сначала надо явно добавить обе вершины, иначе `addDependency` откажет. `plan` использует DFS: состояния 0 — не посещена, 1 — в текущем пути, 2 — завершена. Зависимости обходятся раньше курса, поэтому попадают в результат первыми. Встреча состояния 1 означает цикл: из текущего `path` формируется диагностический путь с повторённой начальной вершиной. Одинаковый порядок добавления вершин и рёбер даёт одинаковый результат. Средняя сложность O(V + E), память O(V + E); рекурсивный DFS может переполнить стек на очень глубоком графе.
## Разбор основных методов по шагам

В `indexBy` создаётся пустая LinkedHashMap. Цикл получает элемент, функция `key.apply(item)` извлекает его ключ, `putIfAbsent` добавляет пару. Если метод вернул прежнее ненулевое значение, ключ уже встречался и выбрасывается ошибка. Нулевые значения запрещены именно для однозначной проверки результата.

В `TagIndex.add` сначала проверяется повтор ID, затем курс добавляется в основную карту. Для каждого тега `computeIfAbsent` находит существующий набор или создаёт новый, после чего ID добавляется в set. При удалении сначала находится исходный курс, затем ID убирается из каждого набора и пустые наборы удаляются из карты.

В `LruCache` конструктор карты получает `true` как accessOrder. Поэтому обращение `cache.get` обновляет порядок. После `put` проверяется размер: `cache.keySet().iterator().next()` возвращает наиболее давно использованный ключ, который удаляется при превышении ёмкости.

В `Graph.visit` state 2 означает, что вершина уже полностью обработана и повторять обход не нужно. State 1 означает, что вершина встречена в текущей цепочке, то есть найден цикл. Иначе вершина помечается активной, добавляется в путь, рекурсивно обходятся prerequisites, затем вершина удаляется из текущего пути, помечается завершённой и добавляется в итоговый порядок.
